# Step 5 — New `coverage` job: combine, `coverage xml`, diff-cover, step summary

See [summary.md](summary.md) for the overall design.

## WHERE

`.github/workflows/ci.yml`

## WHAT

No Python functions beyond calling `tools/ci_coverage_summary.py` (step 2)
as a CLI. New job `coverage`:

- `needs: [unit-tests, integration-tests, langchain-integration]`
- `if:` — identical guard to the `langchain-integration` job (step 4):
  `github.event_name == 'pull_request' || (github.event_name == 'push' &&
  github.ref == 'refs/heads/main')`. This is what keeps the three
  dependencies always-present whenever this job runs — no conditional
  "artifact missing" handling needed.
- Steps: `actions/checkout@v6` with `fetch-depth: 0` (full history — needed
  for `diff-cover` to resolve the PR base; simpler than computing an exact
  shallow depth), `actions/setup-python@v6`, `pip install coverage
  diff-cover`, `actions/download-artifact@v4` with `pattern:
  coverage-data-*`, `path: coverage-data`, `merge-multiple: true`, then:
  - `coverage combine coverage-data` + `coverage xml -o coverage.xml`
  - on `pull_request` only: `diff-cover coverage.xml --compare-branch=
    origin/${{ github.event.pull_request.base.ref }} --markdown-report
    diff-coverage.md` (exit code not checked — advisory only)
  - `python tools/ci_coverage_summary.py --coverage-xml coverage.xml
    --output "$GITHUB_STEP_SUMMARY"` (plus `--diff-report
    diff-coverage.md` only when the diff-cover step ran)

## HOW

This job installs only `coverage` and `diff-cover` directly via `pip`
(no `uv sync`, no project install) — it never imports `mcp_coder`, it
only runs `tools/ci_coverage_summary.py` as a standalone script, which has
no project dependencies. This keeps the job fast and avoids depending on
the full `.[dev,langchain]` environment just to combine coverage files.

## ALGORITHM

1. Download all three `.coverage.*` artifacts flattened into one directory.
2. `coverage combine` over that directory, then `coverage xml`.
3. If this run is for a pull request, run `diff-cover` against the PR
   base, writing its own markdown report (no percentage parsing here —
   diff-cover's own report is embedded as-is by the summary script).
4. Call `tools/ci_coverage_summary.py` to append the headline %, caveat,
   rollup, and (if present) the diff-cover report to the step summary.
5. Nothing in this job can fail the build on a coverage number: no
   `--cov-fail-under`, and the diff-cover step's exit status is not
   checked (don't add `set -e`-sensitive chaining around it; keep it as
   its own `run:` step so a non-zero exit there doesn't cascade — confirm
   via the probe below whether diff-cover's own exit code needs an
   explicit `|| true` to stay non-blocking).

## DATA

N/A — this step wires existing pieces (the artifacts from steps 3/4, the
script from step 2) together in YAML; no new data structures.

## Before writing the `diff-cover` step: confirm its real CLI flags

Don't assume `--compare-branch` / `--markdown-report` from memory. In a
`.scratch/` probe: `pip install diff-cover`, run `diff-cover --help`, and
confirm the actual flag names and whether a non-zero exit code is
possible on "coverage below some default threshold" (if so, add
`|| true` to that `run:` step so it can never fail the job). Delete
`.scratch/` when done.

## Precondition that may not hold

If the probe shows `diff-cover` has no way to (a) compare against a given
branch/ref and (b) produce a report usable in Markdown without a
hard-blocking exit code, write one line to `pr_info/.blocked.txt` and stop.

## Verification

- No local pytest coverage for this step (pure YAML + a probed CLI tool).
- Confirm locally that `tools/ci_coverage_summary.py --coverage-xml ...
  --output -` (or a temp file) works stand-alone against a real
  `coverage.xml` generated by the probe in step 2/this step.
- Push and confirm via `mcp__mcp-workspace__check_branch_status` that the
  `coverage` job runs green on the resulting PR, and that
  `$GITHUB_STEP_SUMMARY` shows the headline %, the caveat, the collapsed
  rollup, and (since this is a PR) the diff-coverage section.
- Confirm `git status` stays clean (no `coverage.xml`/`.coverage*`
  committed) — covered by `.gitignore` from step 1.

## Commit

One commit: the new `coverage` job, message e.g.
`ci: add combined coverage reporting with advisory diff-coverage`.
