# Decisions — I3.1 feasibility spike (#1044)

Decisions taken while refining the step plan. Each entry records what was decided and why.

## Plan review round 1 (log 2), accepted by tech lead

All eight arose from the round-1 plan review recorded in `pr_info/plan_review_log_2.md` and were
approved by the tech lead. They change the plan only — no production code, no CI/`pyproject.toml`
changes (D8 stays confirm-only; the review confirmed no requirement changes are needed).

| ID | Decision | Rationale | Applied in |

| **F1** | The D5 registry probe resolver takes `resolve_from_thread(loop, registry, approval_id, decision)` and does the `registry[approval_id]` → future lookup **inside the thread**, before `call_soon_threadsafe`. Reverse-order ordering and distinct-decision assertions unchanged. | Passing the `Future` object directly bypasses the registry, so the reverse-order scenario only proved "two independent Futures resolve independently" — it would pass green against a completely cross-wired registry, exactly the hazard D5 exists to catch.
