# Decisions — issue #1061 (I2.4)

Decisions taken during plan-review run 2 (see `pr_info/plan_review_log_2.md`). Each was triaged and
confirmed by the user before being applied to the plan.

| # | Topic | Decision | Applied in |
|---|---|---|---|
| R2-1 | **Absent vs present-but-null `tools:`** | `parse_tools_block` branches on `"tools" not in meta` for ABSENT; `raw is None` folds into the MALFORMED branch. `meta.get("tools")` cannot distinguish the two, and treating a present-but-null block as absent is fail-**open** — the exact boundary the AC guards. The test parametrisation names `{"tools": None}` as its own case, distinct from `{"tools": {}}`. | `step_1.md` |
| R2-2 | **Legacy-path enforcement is langchain-only** | The frame map is still built for **every** provider (D12 provider-agnostic blocking), but `build_frame` receives `enforce_skill_tools=ENFORCE_SKILL_TOOLS if provider == "langchain" else False`. The legacy `allowed-tools` list is Claude-provider-native, so a bare flag would block every shell-only skill under the claude provider once #1062 flips the constant. Only `tools_block`-driven blocking is provider-agnostic — all of it, not just the `errors` cases (a well-formed block still blocks via D8's `base: none`/nothing-survived and via bare `use:`/D7b, neither of which sets `errors`). Rationale recorded inline so it is not "simplified" back. | `step_3.md`, `step_4.md`, `summary.md` |
| R2-3 | **Blocked commands stay selectable in the `/` dropdown** | Mark the autocomplete label with `(disabled: <reason>)` but keep the `Option` **enabled** — do not pass `disabled=True`. The AC only requires blocked commands to be *marked*; D7/D9(1) require that *invoking* one prints its reason, and a row that cannot be tab-completed can never be invoked. Separator stays the existing em dash `—`. | `step_4.md` |
| R2-4 | **No `gateway.py` change in Step 2** | `build_legacy_frame` has no `base` local — it passes an inline ternary as `PermissionFrame(base=...)`, which mypy resolves from the argument's `Base` type context. The prescribed "annotate the base local" touch does not exist. | `step_2.md` |
| R2-5 | **`parse_tools_block` locals are initialised up front** | The `use:`+inline error path records an error and falls through to the shared return, so `base`/`allow`/`deny`/`use`/`errors` must all be bound. On a failed `list[str]` check the offending list is left **empty**, so the `advisories` comprehension never calls `.startswith` on a non-string item. | `step_1.md` |
| R2-6 | **D8 predicate reads the *forced* base, with a cause-specific reason** (option C) | `two_empties` keeps evaluating against the post-D3 base, so a dropped `deny` entry that forces `base="none"` **can** block a skill whose `allow` also filtered to empty — D7 ("never burn a turn on a zero-tool skill") wins over D3's "run + warn". **But** `two_empties` returns **two distinct reason strings**: an empty-`allow` reason and a deny-caused reason naming the dropped entry. Reporting an empty `allow` when the block was triggered by an unresolvable `deny` token is a defect; a test asserts the `@ref`-in-`deny` case yields the deny-caused reason. | `step_2.md`, `summary.md` |
| R2-7 | **The refusal guard emits `command_matched`** | A blocked command's event log must have the same shape as every other command's, so the pre-dispatch guard emits `command_matched` alongside `output_emitted` — no replay/event-log asymmetry. | `step_4.md` |
| R2-8 | **Startup notices render outside the runtime-banner branch** | `on_mount` renders the permission notices after the dim banner but **outside** `elif self._core.runtime_info:`, gated only on `resume_log_path is None`. Nesting them inside would silently drop the degraded-config line whenever `runtime_info` is `None` — precisely the invisible failure Step 5 exists to fix. | `step_5.md` |
| R2-9 | **Banner tests go in the existing file** | `format_startup_permission_notices` tests are added to `tests/icoder/test_banner.py` (which already covers `runtime_banner.py`) rather than creating a second `tests/icoder/test_runtime_banner.py`. | `step_5.md`, `summary.md` |
| R2-10 | **The token classifier returns the dropped token, not a bool** | `classify(token, *, side)` returns `dropped: str \| None` (the token itself) and `classify_all` accumulates `dropped: tuple[str, ...]`; `two_empties` takes `deny_dropped: tuple[str, ...]` instead of `deny_forced: bool`. R2-6 requires the deny-caused `blocked_reason` (and the D3 narrowing warning) to **name** the offending entry — a bool cannot, so the promised reason text and its test were unimplementable as written. | `step_2.md` |
| R2-11 | **The arg-scoped `#1053` warning is side-specific** | `classify` already takes `side`; it now selects the wording — `allow` → "arg predicate not enforced until #1053 — elevates the whole tool", `deny` → "… denies the whole tool". An arg predicate over-**denies** on the deny side, so the shared "elevates" text was factually inverted there (the same defect run 1 flagged, reintroduced by a single shared string). A test asserts the deny text never claims elevation. | `step_2.md` |
| R2-12 | **Malformed-block reason joins `tools_block.errors`** | The blocked branch reads `blocked_reason="; ".join(tools_block.errors)`; the bare `errors` in the earlier pseudo-code is unbound in `build_frame` (that local belongs to `parse_tools_block` in Step 1) and would `NameError` if implemented literally. | `step_2.md` |
| R2-13 | **Provider-agnostic blocking is `tools_block`-driven, not `tools_block.errors`-driven** | Reworded to match `summary.md`. All rich-block blocking is provider-agnostic — including the two paths that carry **no** `errors`: D8 (`base: none` with nothing surviving parse) and bare `use:` (D7b). The narrower phrasing invited gating D8/D7b blocking behind `provider == "langchain"`, which would leave those skills silently unblocked outside langchain. Only the **legacy `allowed-tools`** path stays langchain-only (R2-2). | `step_3.md`, `Decisions.md` (R2-2) |
| R2-14 | **Startup notices print the registered (lower-cased) command name** | `format_startup_permission_notices` renders `f"⚠ /{name.lower()} is disabled: …"`. `broken_skills` is keyed by the **raw** skill name from the `{skill_name: SkillFrame}` map, but `register_skill_commands` registers `"/" + skill.name.lower()` (`skills.py:194`), so a mixed-case skill directory would be advertised under a command the user cannot type — and would disagree with the command Step 4's refusal guard matches (`handle_input` lower-cases the leading token). A test covers a mixed-case name. | `step_5.md` |
| R2-15 | **New test files follow the `test_permissions_<module>.py` convention** | `tests/icoder/test_permissions_skill_tools.py` and `tests/icoder/test_permissions_skill_frame.py` (not `test_skill_tools.py` / `test_skill_frame.py`), matching every other `permissions/` module's test file (`test_permissions_matcher.py`, `test_permissions_resolver.py`, `test_permissions_gateway.py`, …). Applies to the WHERE sections, both LLM PROMPTs, Step 3's migration note and the summary's created-files list. | `step_1.md`, `step_2.md`, `step_3.md`, `summary.md` |
| R2-16 | **Ruff joins the per-step verification loop** | The plan's exit criteria were pylint + pytest + mypy + `lint-imports`, but the final AC requires "ruff-docstrings clean" and CI runs `ruff check src tests` with `select = ["D","DOC"]` and `preview = true`. Every new public function returns a value (`parse_tools_block`, `build_frame`, `as_base`, `two_empties`, `format_startup_permission_notices`, `CommandRegistry.get`, `AppCore.broken_skills`), so a missing `Returns:` section trips DOC201 and lands the commit CI-red. `lint-imports` **stays** in the loop even though CI does not run it — the plan being stricter there is intentional. Step 1's prompt also had the wrong tool prefix (`mcp__tools-py__*`); corrected to `mcp__mcp-tools-py__*` in the same clause. | `summary.md`, `step_1.md` … `step_5.md` |
| R2-17 | **The startup-notice block re-queries `OutputLog`** | Step 5's HOW called `output.append_text(...)`, but `output` is bound **only** inside `on_mount`'s `elif self._core.runtime_info:` branch (`ui/app.py:152`) — and R2-8 deliberately renders the notices *outside* that branch. As written it raises `UnboundLocalError` in exactly the `runtime_info is None` case Step 5's own `test_app_pilot` assertion covers. The notices block binds its own `output = self.query_one(OutputLog)`. Same class of defect as R2-12's unbound `errors`. | `step_5.md` |
| R2-18 | **Step 3 updates the docstrings that describe the deleted code** | Deleting `build_legacy_frame` leaves two docstrings describing a function that no longer exists: `gateway.py`'s module-docstring third paragraph, and `RealLLMService.stream`'s docstring (its `allowed_tools` `Args:` entry plus the paragraph and `Yields:` note about building the frame and emitting a `permission_warning` per malformed token — both behaviours move to `AppCore` in Step 3). Neither ruff nor pylint flags stale prose, so the plan has to say so explicitly. | `step_3.md` |
